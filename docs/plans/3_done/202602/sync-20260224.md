**対象ファイル**: `go/Makefile`

**差分の内容**:

- **Mewst**: CI 環境とローカル環境で分岐（CI: `-short` フラグ付き、ローカル: `op run` 経由）
- **Annict**: 分岐なし。常に `go test -json -race ./... | tparse -all`
- **Wikino**: 分岐なし。常に `go test -json -race ./... | tparse`

**採用方針**:

- [ ] Mewst の方式を採用（他プロジェクトに反映）
- [ ] Annict の方式を採用（他プロジェクトに反映）
- [ ] Wikino の方式を採用（他プロジェクトに反映）
- [ ] スキップ（対応不要）
- [x] その他: AnnictかWikinoの方針を採用したいので、`tparse -all` と `tparse` の違いを教えてください

**`tparse -all` と `tparse` の違い**:

| オプション    | 表示内容                                                                | 用途             |
| ------------- | ----------------------------------------------------------------------- | ---------------- |
| `tparse`      | パッケージサマリーテーブル + **失敗テストのみ**ハイライト表示           | 通常のテスト実行 |
| `tparse -all` | パッケージサマリーテーブル + **全テスト（合格含む）**を個別にリスト表示 | デバッグ用       |

**推奨**: Wikino 方式（`tparse`）を `make test` に採用し、`make test-verbose` は既存の `tparse -all` を維持する。これにより通常のテスト実行では失敗テストのみが目立ち、デバッグ時には全テストを確認できる。
