# プロジェクト間ファイル同期コマンドの汎用化 作業計画書

## 仕様書

- 新規作成予定: `docs/specs/sync-command.md`

## 概要

現在の `/sync-guideline` コマンドは CLAUDE.md と `go/docs/` 配下のガイドラインファイルのみを比較対象としているが、実際にはプロジェクト間で共通化できるファイルは他にも多数存在する（`Dockerfile.dev`、`.golangci.yml`、`Makefile`、CI ワークフローなど）。

これらのファイルも含めた汎用的な同期コマンドに改善し、以下を実現する：

- **対象ファイルの拡張**: ガイドライン以外の設定ファイル・CI ワークフロー等も同期対象とする
- **コンテキスト制限の回避**: Task tool を使った並列差分調査（Wikino 版で導入済みの仕組み）
- **作業計画書ベースのワークフロー**: 比較後に `docs/plans/template.md` をコピーした作業計画書を作成し、差分レポート・採用方針・タスクリストを一元管理する
- **採用方針の選択**: 各差分に対してどのプロジェクトの方式を採用するかをユーザーが選択できる

## 要件

### 機能要件

- `/sync` 実行時に、全カテゴリのファイルをプロジェクト間で比較する
- `docs/plans/template.md` をコピーして作業計画書を作成する
- 作業計画書の「設計」セクション内に、カテゴリ別の差分レポートを記入する
- 各差分に対して採用方針のチェックボックスを用意し、ユーザーが選択できるようにする
- ユーザーが採用方針を記入した後、プロジェクトごとのタスクリストを生成する
- コンテキスト制限を回避するため、Task tool でカテゴリ別に並列で差分調査を行う

## 実装ガイドラインの参照

この作業計画書はコマンドファイル（`.claude/commands/sync.md`）の作成・更新であり、Go 版・Rails 版の実装コードは伴いません。

### コマンドの構成

`.claude/commands/sync.md` に以下を記載する：

1. **対象プロジェクト一覧**: ディレクトリパスの定義
2. **比較対象ファイル一覧**: カテゴリ別のファイル一覧
3. **スキップ済みの差分一覧**: 過去にスキップと判断された差分の概要を記録するセクション
4. **手順**:
   - ステップ 1: 作業計画書の作成（`docs/plans/template.md` をコピー）
   - ステップ 2: カテゴリ別の並列差分調査（Task tool 使用、スキップ済み差分は無視）
   - ステップ 3: 差分レポートの記入（採用方針チェックボックス付き）
   - ステップ 4: タスクリストの初期タスクを用意（ユーザーによる採用方針記入タスク + Claude によるタスクリスト作成タスク）
   - ステップ 5: ユーザーへの報告
   - ステップ 6: スキップ済み差分の更新（採用方針で「スキップ」が選ばれた差分をコマンドファイルに追記）
5. **注意事項**

### ワークフロー

#### ステップ 1: 作業計画書の作成

`docs/plans/template.md` をコピーして以下のパスに作成する：

```
docs/plans/1_doing/sync-YYYYMMDD.md
```

タイトルは「プロジェクト間ファイル同期 YYYY/MM/DD」とする。

#### ステップ 2: カテゴリ別の並列差分調査

**重要**: コンテキスト制限を回避するため、カテゴリごとに Task tool（subagent_type: `general-purpose`）を使って並列で差分調査を行う。

各 Task tool には以下を指示する：

- 指定されたカテゴリのファイルを全プロジェクト間で比較する
- 存在しないファイルはスキップする
- 差分がないファイルは「差分なし」と明記する
- プロジェクト名のみの差異は差分として報告しない
- 実質的な内容の違い（設計方針、設定値、セクションの有無等）を報告する
- **スキップ済みの差分一覧に記載されている差分は無視する**（レポートに含めない）

#### ステップ 3: 差分レポートの記入

作業計画書の「設計」セクション内に、以下の形式で記入する：

```markdown
### 差分 1: [差分の概要]

**対象ファイル**: `go/docs/validation-guide.md`

**差分の内容**:
- **Mewst**: [Mewst での記述内容の要約]
- **Annict**: [Annict での記述内容の要約]
- **Wikino**: [Wikino での記述内容の要約]

**採用方針**:
- [ ] Mewst の方式を採用（他プロジェクトに反映）
- [ ] Annict の方式を採用（他プロジェクトに反映）
- [ ] Wikino の方式を採用（他プロジェクトに反映）
- [ ] スキップ（対応不要）
- [ ] その他: <!-- 記入 -->

---
```

#### ステップ 4: タスクリストの初期タスクを用意

```markdown
## タスクリスト

### フェーズ 1: 採用方針の決定

- [ ] **1-1**: 差分レポートを確認し、各差分の採用方針を記入する
  - 各差分の「採用方針」チェックボックスにチェックを入れる
  - 必要に応じて「その他」に補足を記入する
  - **担当**: ユーザー

### フェーズ 2: タスクリストの作成

- [ ] **2-1**: 採用方針を元に自プロジェクトのタスクリストを追加する
  - ユーザーが記入した採用方針に基づき、フェーズ 3 以降に自プロジェクトの具体的なタスクを追加する
  - 他プロジェクトへの反映は、各プロジェクトで `/sync` を実行して対応する
  - **担当**: Claude
```

#### ステップ 5: ユーザーへの報告

1. 作成した作業計画書のパス
2. 発見した差分の件数（カテゴリ別の内訳）
3. 「各差分の **採用方針** のチェックボックスにチェックを入れてください。記入後にタスクリストを更新します。」

#### ステップ 6: スキップ済み差分の更新

ユーザーが採用方針で「スキップ（対応不要）」を選んだ差分について、`.claude/commands/sync.md` の「スキップ済みの差分」セクションに概要を追記する。

```markdown
## スキップ済みの差分

<!-- 過去の /sync 実行で「スキップ（対応不要）」と判断された差分です -->
<!-- 次回以降の /sync ではこの一覧に該当する差分はレポートに含めません -->
<!-- 再度確認が必要になった場合は該当行を削除してください -->

- `go/CLAUDE.md`: Go バージョンの違い（プロジェクト固有のため）
- `go/docs/security-guide.md`: スペースIDによるクエリスコープ（Wikino 固有の機能）
```

これにより、次回の `/sync` 実行時にスキップ済みの差分が自動的に無視される。ユーザーが再確認したい場合は該当行を削除すればよい。

### 既存コマンドとの関係

- `.claude/commands/sync-guideline.md` を `.claude/commands/sync.md` にリネーム（内容を全面刷新）
- 同時に Annict・Wikino にも同等のコマンドを配置する（プロジェクト名・ディレクトリパスを調整）

### 作業計画書テンプレートのカスタマイズ

`docs/plans/template.md` をそのまま使用するが、`/sync` コマンドで作成する際に以下のセクションを自動でカスタマイズする：

- **概要**: 同期の目的と対象プロジェクト、比較対象ファイル一覧を記載
- **設計**: 差分レポート・採用方針セクション（Claude が記入）
- **タスクリスト**: 空の状態で作成（プロジェクトごとのフェーズ枠のみ）
- **不要なセクション**: 「要件」「実装ガイドラインの参照」「非機能要件」は削除してシンプルにする

## 採用しなかった方針

### `/sync-guideline` の名前を維持する案

対象がガイドライン以外にも広がるため、コマンド名と実際の機能が乖離する。`/sync` というシンプルな名前のほうが直感的。

### ファイルごとに自動 diff を取る案

`diff` コマンドで機械的に差分を取る方式も検討したが、プロジェクト名の置換だけの差異と実質的な設計方針の差異を区別できないため、Claude による意味的な比較のほうが適切。

### docker-compose.yml や mise.toml を同期対象に含める案

これらのファイルはプロジェクト固有の設定（ポート番号、サービス構成、バージョン）が多く、同期すると逆に混乱するため除外した。
