### `go/internal/usecase/create_sign_in.go`: Validator の返り値の型が作業計画書と異なる

**ステータス**: 要確認

**チェックしたガイドライン**:

- [作業計画書 タスク 6-1](/workspace/docs/plans/1_doing/depguard-alignment.md) - 設計仕様

**問題点・改善提案**:

- **作業計画書との乖離**: 作業計画書のタスク 6-1 では「`SignInCreateValidator` の Result 型を廃止し `(*model.User, error)` 返しに変更」と記載されているが、実装では `(*SignInCreateValidatorOutput, error)` を返している。`SignInCreateValidatorOutput` は `User *model.User` のみを含む構造体。

  ```go
  // 作業計画書の設計
  func (v *SignInCreateValidator) Validate(ctx, input) (*model.User, error)

  // 実際の実装
  type SignInCreateValidatorOutput struct {
      User *model.User
  }
  func (v *SignInCreateValidator) Validate(ctx, input) (*SignInCreateValidatorOutput, error)
  ```

  Output 構造体を使うパターンは UseCase の Input/Output パターンと一貫性があり、将来の拡張性も高いため、実装のほうが良い判断と思われる。ただし、意図的な変更であれば作業計画書の設計セクションを更新すべき。

  **修正案**:

  作業計画書の該当箇所を実装に合わせて更新する（設計が実装中に改善された場合は計画書に反映する原則に従う）。

## 総合評価

**評価**: Approve

**総評**:

タスク 6-1（パイロット: sign_in UseCase にバリデーションを統合）が正確に実装されている。主要な変更点：

1. **UseCase の新設**: `CreateSignInUsecase` が Validator 呼び出し → Actor 取得 → セッション作成のフローを一元管理しており、Handler がシンプルになった
2. **Validator の `(data, error)` パターン移行**: `Result` 型を廃止し、`model.ValidationError` を `error` として返す Go 慣習的な設計に変更
3. **Handler の `errors.As` パターン**: `handleCreateError` メソッドで `model.AsValidationError` を使ったエラー判別が適切に実装されている
4. **テンプレートの段階的移行**: sign_in テンプレートは `model.ValidationError` に直接移行、他テンプレートは `.ToValidationError()` ブリッジで中間状態を維持

テストは UseCase テスト（正常系 2 件 + 異常系 3 件）、Validator テスト（形式バリデーション 5 件 + 状態バリデーション 7 件）、Handler テスト（既存テストの更新）と十分にカバーされている。

唯一の指摘は Validator 返り値の型が作業計画書と微差がある点だが、実装のほうが一貫性があり、Approve 判定に影響しない。
