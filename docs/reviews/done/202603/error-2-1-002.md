### 各ファイルのチェック内容

**`go/internal/handler/errors.go`**:

- `BadGateway` ヘルパー関数は既存の `NotFound` と同じパターンで実装されており、一貫性がある
- `slog.ErrorContext` でエラーログを適切に出力している（[@go/CLAUDE.md#ログ出力]）
- Content-Type ヘッダーの設定を `NotFound` にも追加しており、一貫性が向上している
- ミドルウェアから `handler` パッケージへの依存を避けるため、ミドルウェア側では直接テンプレートを使用している（[@go/docs/architecture-guide.md] のミドルウェアの依存関係ルールに準拠）

**`go/internal/middleware/reverse_proxy.go`**:

- `render502ErrorHTML()` 関数（65行のハードコードHTML）を削除し、templ テンプレートに置き換え
- ミドルウェアの依存関係は `templates` と `i18n`（いずれもPresentation層のヘルパー）で、アーキテクチャルールに準拠（[@go/docs/architecture-guide.md#Presentation層]）
- `handler` パッケージには依存せず、直接 `errors.BadGateway().Render()` を呼び出している（アーキテクチャルール: ミドルウェアは handler に依存しない）
- ロケール検出と Content-Type 設定が適切に行われている

**`go/internal/templates/pages/errors/bad_gateway.templ`**:

- 既存の `not_found.templ` と同じ構造・スタイルで一貫性がある（[@go/docs/templ-guide.md]）
- スタンドアロン方式（外部CSS・レイアウト依存なし）で作業計画書の設計方針に準拠
- `templates.Locale(ctx)` と `templates.T(ctx, ...)` による国際化対応（[@go/docs/i18n-guide.md]）
- `.submessage` クラスの追加は502ページ固有の2行メッセージに対応するもので適切

**`go/internal/i18n/locales/ja.toml` / `en.toml`**:

- 翻訳キーの命名規則 `error_bad_gateway_{detail}` が既存の `error_not_found_{detail}` と一貫している（[@go/docs/i18n-guide.md#翻訳の命名規則]）
- `description` フィールドが全キーに記述されている
- `error_bad_gateway_title` は作業計画書に明示されていないが、`<title>` タグで使用しており、既存の `error_not_found_title` との一貫性から妥当

**`go/internal/handler/errors_test.go`**:

- `TestBadGateway`: ステータスコード、日本語/英語メッセージ、ホームリンクのテストを網羅
- `TestBadGatewayTemplate`: テーブル駆動テストで日英両方のテンプレートレンダリングを検証（[@go/CLAUDE.md#テーブル駆動テストの書き方]）
- `t.Parallel()` を全テストで使用（[@go/CLAUDE.md#テストのベストプラクティス]）
- 既存の `TestNotFound` / `TestNotFoundTemplate` と同じテストパターンで一貫性がある
