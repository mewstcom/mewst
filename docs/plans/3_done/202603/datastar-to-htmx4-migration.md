## 概要

<!--

Go 版 Mewst のハイパーメディアフレームワークを Datastar v1.0.0-RC.6（CDN 経由）から htmx 4 に移行する。

移行の動機:

- **コミュニティの規模**: htmx のほうがコミュニティが大きく、情報や事例が豊富
- **過剰な依存**: 現在の使用箇所はフォーム二重送信防止（6 箇所）のみであり、Datastar のリアクティブシグナル機能は過剰
- **依存関係のシンプルさ**: htmx 単体で現在の全ユースケースをカバーでき、CDN 依存も解消できる
- **Wikino との統一**: 姉妹プロジェクトの Wikino で同様の移行を完了しており、技術スタックを統一することで保守性が向上する

現在の Datastar 使用状況は非常に限定的で、Go SDK（`datastar-go`）への依存もなく、SSE やフラグメント更新も未使用。フォームの `$isSubmitting` シグナルによるボタン無効化のみに使用している。

### パターン別の移行設計

#### パターン 1: フォーム二重送信防止（6 ファイル）

**現在（Datastar）**:

```templ
<form data-on:submit__passive="$isSubmitting = true">
  <button data-attr:disabled="$isSubmitting == true">送信</button>
</form>
```

**移行後（htmx 4）**:

```templ
<form hx-on:submit="disableSubmitButtons(this)" method="POST" action="/path">
  <button type="submit">送信</button>
</form>
```

`disableSubmitButtons` は `web/main.js` に定義するグローバル関数で、フォーム内の全送信ボタンを disabled にする。htmx 4 の `hx-on:submit` は通常の DOM イベントリスナーとして動作するため、htmx 経由でないフォーム送信でも機能する。通常の HTML フォーム送信（`method="POST" action="/path"`）を維持したまま、テンプレートを見るだけで送信時の挙動がわかる。

### JS ベンダーファイルの配置

- htmx 4 の JS ファイルを `go/static/js/vendor/htmx-4.0.0.js`（リリースバージョンに合わせる）として配置
- `head.templ` の CDN 読み込みをローカルベンダーファイルに差し替え
- CDN 依存を解消し、オフラインでも動作するようにする

### CSRF 対策

現在の Mewst は通常の HTML フォーム送信を使用しており、`<input type="hidden" name="csrf_token">` でトークンを送信している。htmx 4 移行後もこの方式は変わらないため、既存の CSRF ミドルウェアがそのまま機能する。

### Datastar を除去するだけで htmx を導入しない

現在のフォーム二重送信防止は、Datastar を除去して純粋な JavaScript で実装することも可能。しかし、htmx を導入することで以下のメリットがある：

- 将来的にページネーション、フラグメント更新、OOB スワップなどの機能を追加する際に基盤が整う
- Wikino と技術スタックが統一される
- `hx-on:submit` による宣言的なイベントハンドリングで、テンプレートの可読性が向上する

### フォーム送信を `hx-post` に変換して `hx-disable` を使用する

htmx 4 の `hx-disable` はリクエスト中に要素を自動で disabled にするが、htmx 経由（`hx-post` 等）でフォーム送信される場合のみ機能する。フォームを `hx-post` 化すれば `hx-disable` が使えるが、以下の理由で不採用とした：

- ハンドラー側の変更が必要（成功時は `HX-Redirect` ヘッダー、エラー時はフォーム HTML の再レンダリング）で、テンプレート変更だけでは完結しない
- 対象ハンドラーが多岐にわたり（sign_in, sign_up, password_reset, password, email_confirmation, accounts）、影響範囲が大きい

代わりに `hx-on:submit` による DOM イベントリスナー方式を採用した。通常の HTML フォーム送信を維持したまま、テンプレート変更のみで二重送信防止を実現できる。

以下の機能は今回の実装では**実装しません**：

- **htmx 4 の SSE extension の導入**: 現時点では SSE が必要なユースケースがないため、通常の HTML レスポンスで対応する。将来的にリアルタイム更新が必要になった場合に検討する
